第 7 章 推理与生成：模型如何"说话" ​

对应代码：eval_llm.py、model/model_minimind.py 的 MiniMindForCausalLM.generate、scripts/ 下的推理服务

本章目标：逐行读懂 MiniMind 自实现的 generate（采样策略、温度、top-k/top-p、重复惩罚、KV Cache、流式输出），掌握 CLI/WebUI/OpenAI API 三种推理入口，并理解 RoPE 外推（YaRN）的正确用法。

7.1 生成任务的本质 ​

训练时模型一次处理整段序列（Teacher Forcing）；推理时只能逐 token 生成：

text
输入: [user]你好[/user]assistant → 预测 P(下一个 token)
采样出 "我" → 拼接到输入 → 预测 P(再下一个)
采样出 "是" → 拼接到输入 → ...
直到生成 <|im_end|>（EOS）或达到长度上限

每一步的完整成本 = 一次完整前向（随着序列变长，注意力成本增加）。KV Cache（第 4 章 4.3.3）让历史 K/V 免于重算，把每步成本从 O(T²) 降到 O(T)。

7.2 逐行精读 generate（model_minimind.py 第 255~288 行） ​

python
@torch.inference_mode()
def generate(self, inputs=None, attention_mask=None, max_new_tokens=8192, temperature=0.85,
             top_p=0.85, top_k=50, eos_token_id=2, streamer=None, use_cache=True,
             num_return_sequences=1, do_sample=True, repetition_penalty=1.0, **kwargs):
    input_ids = kwargs.pop("input_ids", inputs).repeat(num_return_sequences, 1)
    attention_mask = attention_mask.repeat(num_return_sequences, 1) if attention_mask is not None else None
    past_key_values = kwargs.pop("past_key_values", None)
    finished = torch.zeros(input_ids.shape[0], dtype=torch.bool, device=input_ids.device)
    if streamer: streamer.put(input_ids.cpu())
    for _ in range(max_new_tokens):
        past_len = past_key_values[0][0].shape[1] if past_key_values else 0
        outputs = self.forward(input_ids[:, past_len:], attention_mask, past_key_values, use_cache=use_cache, **kwargs)
        attention_mask = torch.cat([attention_mask, attention_mask.new_ones(attention_mask.shape[0], 1)], -1) if attention_mask is not None else None
        logits = outputs.logits[:, -1, :] / temperature
        if repetition_penalty != 1.0:
            for i in range(input_ids.shape[0]):
                seen = torch.unique(input_ids[i]); score = logits[i, seen]
                logits[i, seen] = torch.where(score > 0, score / repetition_penalty, score * repetition_penalty)
        if top_k > 0:
            logits[logits < torch.topk(logits, top_k)[0][..., -1, None]] = -float('inf')
        if top_p < 1.0:
            sorted_logits, sorted_indices = torch.sort(logits, descending=True)
            mask = torch.cumsum(torch.softmax(sorted_logits, dim=-1), dim=-1) > top_p
            mask[..., 1:], mask[..., 0] = mask[..., :-1].clone(), 0
            logits[mask.scatter(1, sorted_indices, mask)] = -float('inf')
        next_token = torch.multinomial(torch.softmax(logits, dim=-1), num_samples=1) if do_sample else torch.argmax(logits, dim=-1, keepdim=True)
        if eos_token_id is not None:
            next_token = torch.where(finished.unsqueeze(-1), next_token.new_full((next_token.shape[0], 1), eos_token_id), next_token)
        input_ids = torch.cat([input_ids, next_token], dim=-1)
        past_key_values = outputs.past_key_values if use_cache else None
        if streamer: streamer.put(next_token.cpu())
        if eos_token_id is not None:
            finished |= next_token.squeeze(-1).eq(eos_token_id)
            if finished.all(): break
    if streamer: streamer.end()
    if kwargs.get("return_kv"): return {'generated_ids': input_ids, 'past_kv': past_key_values}
    return input_ids

逐段精读：

7.2.1 初始化与循环骨架 ​

python
@torch.inference_mode()                    # 等价 no_grad + 部分优化，推理专用
...
input_ids = inputs.repeat(num_return_sequences, 1)   # 支持一次生成多条（beam 风格扩展位）
finished = torch.zeros(batch, dtype=torch.bool)      # 每条序列的"是否已结束"标记
for _ in range(max_new_tokens):
    past_len = past_key_values[0][0].shape[1] if past_key_values else 0
    outputs = self.forward(input_ids[:, past_len:], ...)  # ★ 只前向"新 token"！

核心优化：每次循环只把"新生成的那个 token"送入模型（input_ids[:, past_len:]），历史部分完全由 KV Cache 提供——这正是 7.1 说的 O(T) 每步成本。第一次迭代 past_key_values=None，past_len=0，输入是完整提示词。

7.2.2 温度（Temperature） ​

python
logits = outputs.logits[:, -1, :] / temperature

取最后一个位置的 logits（形状 (B, V)），除以温度：

pt(v)=exp⁡(zv/T)∑uexp⁡(zu/T)
  • T=1：原始分布；
  • T<1（如 0.85）：分布变"尖锐"，高概率 token 更突出——回答更确定、更保守；
  • T>1：分布变"平坦"，低概率 token 机会增大——回答更多样、更有"创意"但也更离谱；
  • T→0：退化为 argmax（贪心）。

7.2.3 重复惩罚（Repetition Penalty） ​

python
seen = torch.unique(input_ids[i])
score = logits[i, seen]
logits[i, seen] = torch.where(score > 0, score / repetition_penalty, score * repetition_penalty)

对已出现过的 token：正 logits 除以惩罚系数（压低），负 logits 乘以系数（推高）——整体压低重复 token 的概率。repetition_penalty=1.0 时跳过（MiniMind 默认关闭，因为惩罚会损害小模型的表达能力，需要时可手动开）。

7.2.4 Top-K 截断 ​

python
if top_k > 0:
    logits[logits < torch.topk(logits, top_k)[0][..., -1, None]] = -float('inf')

只保留 logits 最大的 k 个 token（默认 50），其余置 −∞（softmax 后概率为 0）。防止采样到概率极低的"垃圾 token"。

7.2.5 Top-P（Nucleus Sampling，核采样） ​

python
sorted_logits, sorted_indices = torch.sort(logits, descending=True)
mask = torch.cumsum(torch.softmax(sorted_logits, dim=-1), dim=-1) > top_p
mask[..., 1:], mask[..., 0] = mask[..., :-1].clone(), 0          # 至少保留 1 个 token
logits[mask.scatter(1, sorted_indices, mask)] = -float('inf')

从概率最高的 token 开始累加，保留累积概率恰好超过 top_p（0.85）的集合，其余截断。与 top-k 的区别：top-k 固定数量，top-p 自适应数量（分布尖锐时保留少、平坦时保留多）。

注意 mask[..., 1:], mask[..., 0] = mask[..., :-1].clone(), 0：把 mask 右移一位并强制首位为 False——保证至少留下概率最高的 1 个 token，防止极端分布下集合为空。

7.2.6 采样与终止 ​

python
next_token = torch.multinomial(torch.softmax(logits, dim=-1), num_samples=1) if do_sample \
             else torch.argmax(logits, dim=-1, keepdim=True)
  • do_sample=True：从分布中随机采样（多样性）；
  • do_sample=False：贪心取 argmax（确定性，但易重复循环）。
python
finished |= next_token.squeeze(-1).eq(eos_token_id)   # 生成 EOS 即标记完成
if finished.all(): break                                # 全部完成才提前退出

已完成的序列后续强制输出 EOS（torch.where 那行）——保证所有序列等长，方便矩阵化。

7.2.7 流式输出 ​

python
if streamer: streamer.put(next_token.cpu())

TextStreamer（transformers 提供）把 token 逐块解码打印，实现"打字机效果"。streamer.put(input_ids.cpu()) 先推送提示词（skip_prompt=True 时不显示）。

7.3 eval_llm.py：CLI 评测入口精读 ​

7.3.1 权重加载的两种模式（第 12~30 行） ​

python
def init_model(args):
    tokenizer = AutoTokenizer.from_pretrained(args.load_from)
    if 'model' in args.load_from:                      # 模式 A：原生 PyTorch 权重
        model = MiniMindForCausalLM(MiniMindConfig(...))
        ckp = f'./{args.save_dir}/{args.weight}_{args.hidden_size}{moe_suffix}.pth'
        model.load_state_dict(torch.load(ckp, map_location=args.device), strict=True)
        if args.lora_weight != 'None':
            apply_lora(model)
            load_lora(model, f'./{args.save_dir}/{args.lora_weight}_{args.hidden_size}.pth')
    else:                                              # 模式 B：Transformers 格式
        model = AutoModelForCausalLM.from_pretrained(args.load_from, trust_remote_code=True)
    return model.half().eval().to(args.device), tokenizer
  • 模式 A（--load_from model）：加载自己训练/下载的 .pth 权重，需要手动指定 --weight 前缀（pretrain/full_sft/...）；strict=True 保证权重与模型配置严格匹配（配置不一致会直接报错，这是好事）；
  • 模式 B（--load_from ./minimind-3）：加载 transformers 格式模型目录（第 1 章快速体验用的就是这个）；
  • 注意 model.half()：权重是 fp16 存储，推理统一转 fp16 省显存提速；
  • LoRA 加载（第 8 章主角）：apply_lora 给所有方阵 Linear 挂上 LoRA 分支，load_lora 灌入训练好的低秩权重。

7.3.2 输入构建（第 71~78 行） ​

python
if 'pretrain' in args.weight:
    inputs = tokenizer.bos_token + prompt                        # 预训练模型：裸文本 + bos
else:
    inputs = tokenizer.apply_chat_template(conversation, tokenize=False,
                                           add_generation_prompt=True,
                                           open_thinking=bool(args.open_thinking))
  • 预训练模型没见过对话模板 → 直接喂裸文本（第 5 章实验 5.2 的现象解释）；
  • SFT 后的模型走 chat_template：add_generation_prompt=True 在末尾追加 <|im_start|>assistant\n<think>\n（或空 think），模型从此位置开始续写；
  • open_thinking=1 时模板注入 <think>\n（思考模式），0 时注入空 <think>\n\n</think>\n\n（直答模式）——同一模型两种行为，纯模板层切换（第 11 章详解）。

7.4 RoPE 外推与 YaRN 的正确理解 ​

bash
python eval_llm.py --weight full_sft --inference_rope_scaling

这个开关做什么（对应第 4 章 4.3.2 的 YaRN 分支）：

  1. 设置 inference_rope_scaling=True → config 注入 rope_scaling（factor=16，原训练长度 2048）；
  2. precompute_freqs_cis 检测 end / orig_max > 1（32768/2048 = 16 > 1）→ 对低频维度做频率拉伸（ramp 过渡）；
  3. 模型在超过训练长度的位置也能获得合理的相对位置编码。

必须澄清的边界：

  • ✅ YaRN 解决的是"位置编码断裂"：不处理时，超长位置上的 RoPE 角速度与训练分布不一致，注意力计算错乱（表现为输出崩溃/重复）；
  • ❌ YaRN 不产生长文本能力：模型训练时最长 768 tokens，它根本没"见过"更长的依赖结构，外推只是"不崩"，不是"会读长文"；
  • 实际体验：外推 2~4 倍长度通常质量尚可，16 倍（factor=16）时注意观察退化。

7.7 本章小结 ​

  • 推理 = 逐 token 前向 + KV Cache 复用历史；generate 只前向新 token，成本 O(T)/步；
  • 采样管线：温度 → 重复惩罚 → top-k → top-p → multinomial；每个环节都是"控制多样性/质量的旋钮"；
  • do_sample=False 退化为贪心；EOS 触发终止，finished 掩码保证批内等长；
  • eval_llm.py 双模式加载（原生 .pth / transformers 目录），对话模板 + open_thinking 开关注入；
  • YaRN 只治"位置编码断裂"，不凭空产生长文本能力；
  • 三种部署：CLI / Streamlit WebUI / OpenAI 兼容 API，一次训练全生态可用。

7.8 思考题 ​

  1. 温度 T→0 时采样分布收敛到什么？T→∞ 呢？分别对应什么生成行为？
  2. top-k=1 时模型行为如何？这与 do_sample=False 有何异同？
  3. 为什么重复惩罚对已见 token 的正负 logits 要区别处理（除 vs 乘）？如果统一乘一个小于 1 的系数会怎样？
  4. KV Cache 在长上下文推理中还有哪些资源消耗？（提示：缓存大小与序列长度、层数、头数的关系）
  5. （动手）用 return_kv 参数（generate 的隐藏功能）观察 past_key_values 的结构，验证第 4 章的 GQA 形状推导。
  6. --historys 2 时，第三次提问的输入包含哪几轮消息？画出 chat_template 渲染后的完整文本。
