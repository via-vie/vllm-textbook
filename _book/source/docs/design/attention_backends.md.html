8## Setting the Attention Backend
9
10### Command Line
11
12There are two ways to specify the backend from the command line:
13
14**Option 1: Using `--attention-backend` (simple)**
15
16```bash
17vllm serve <model> --attention-backend FLASH_ATTN
18```
19
20**Option 2: Using `--attention-config.backend` / `-ac.backend` (structured config)**
21
22```bash
23# Dot notation
24vllm serve <model> --attention-config.backend FLASH_ATTN
25vllm serve <model> -ac.backend FLASH_ATTN
26
27# JSON format
28vllm serve <model> --attention-config '{"backend": "FLASH_ATTN"}'
29vllm serve <model> -ac '{"backend": "FLASH_ATTN"}'
30```
31
32> **Note:** `--attention-backend` and `--attention-config.backend` are mutually
33> exclusive. Use one or the other, not both.
34
35### Python API
36
37Use `AttentionConfig` with the `LLM` class:
38
39```python
40from vllm import LLM
41from vllm.config import AttentionConfig
42from vllm.v1.attention.backends.registry import AttentionBackendEnum
43
44# Method 1: Using AttentionConfig with enum
45llm = LLM(
46 model="Qwen/Qwen3-0.6B",
47 attention_config=AttentionConfig(backend=AttentionBackendEnum.FLASH_ATTN),
48)
49
50# Method 2: Using attention_backend parameter with string
51llm = LLM(
52 model="Qwen/Qwen3-0.6B",
53 attention_backend="FLASH_ATTN",
54)
55```

57## Backend Selection Behavior
58
59### Triton/FlashAttention Composite
60
61On Hopper, `TRITON_FLASH_ATTN` is preferred for compatible multimodal-prefix
62configurations. It uses Triton when the current queries need bidirectional
63image attention and FlashAttention for causal text prefills and decode, with a
64shared KV cache. The causal child must resolve to FA4. This happens
65automatically for FA4-only shapes such as head size 512 and models whose
66version policy promotes all layers to FA4, including Gemma 4. A standalone
67head-size-256 configuration whose version policy selects FA3 falls back to
68Triton for the whole layer.
69
70No attention override is needed for supported multimodal models:
71
72```bash
73vllm serve google/gemma-4-31B-it
74```
75
76### Triton/FlashInfer Composite
77
78On Blackwell, `TRITON_FLASHINFER` is preferred for compatible
79multimodal-prefix configurations, including Gemma 4 with BF16 or FP8 KV cache. It uses
80Triton when a batch's current queries require bidirectional image attention,
81and FlashInfer for causal text prefills and decode. Historical image tokens
82alone do not select Triton.
83
84This instantiates `create_composite_attention_backend` from
85`vllm/v1/attention/backends/composite.py` with Triton,
86FlashInfer, and `MMPrefixAttentionRouting`. The reusable factory owns child
87implementations, metadata dispatch, compatible cache requirements, and workspace
88sharing. The routing policy selects the child and defines graph-capture safety.
89Other combinations can reuse the same machinery.
90
91The backend supports head dimensions 256/512, FP16/BF16 and FP8 KV cache,
92and 64-token kernel pages with a head-major cache layout. TRTLLM handles causal
93attention at both head dimensions; its hdim512 kernels do not support 128-token
94pages.
95For Gemma 4, full CUDA graphs cover single-token batches; multi-token batches
96use the non-full-graph execution path. Models whose image masks extend beyond
97the sliding window cannot use full attention graphs with this composite.
98Context parallelism, R-SWA, attention sinks,
99and adaptive verification are not supported by this composite.
100
101It can also be selected explicitly:
102
103```bash
104vllm serve google/gemma-4-31B-it \
105 --attention-backend TRITON_FLASHINFER
106```
107
108### Manual Selection
109
110When you explicitly set a backend via `--attention-backend` or `AttentionConfig`:
111
1121. The backend is **validated** against your configuration (model dtype, head
113 size, compute capability, etc.)
1142. If the backend **doesn't support** your configuration, an error is raised
115 with the specific reason
1163. If valid, the backend is used
117
118Example error when selecting an incompatible backend:
119
120```text
121ValueError: Selected backend FLASHMLA is not valid for this configuration.
122Reason: ['compute capability not supported']
123```
124
125### Automatic Selection
126
127When no backend is specified (the default):
128
1291. vLLM iterates through backends in **priority order** (see tables below)
1302. Each backend is validated against your configuration
1313. The **first compatible backend** is selected
1324. If no backend is compatible, an error is raised listing all backends and
133 their incompatibility reasons
134

173
174--8<-- "gen:table-standard"

181> by a dedicated FA4 kernel that requires a KV cache block size of 128 (advertised
182> automatically, so it is picked as long as `--block-size` is not pinned) and does not
183> support logit soft capping, attention sinks, mm_prefix/R-SWA masking, DCP, or windowed
184> encoder attention. Those configurations transparently fall back to FA2. A pinned
185> `--block-size` that is not a multiple of 128 instead makes FlashAttention ineligible
186> for such models, which is an error if the backend was requested explicitly.

198## MiniMax M3 Sparse Attention Backends
199
200Block-sparse GQA backend used by MiniMax M3 sparse ("lightning indexer")
201layers. It is wired in directly by the model and is not part of the
202automatic priority lists above. A lightning indexer scores KV blocks, the
203top-k blocks (plus fixed init/local blocks) are selected, and attention
204attends only to those blocks; index keys live in a separate side cache.

208## MLA (Multi-head Latent Attention) Backends
209
210MLA uses separate backends for prefill and decode phases.
211
212### Prefill Backends
213
214To explicitly select a prefill backend, use
215`-ac.mla_prefill_backend=<BACKEND>` (e.g., `FLASH_ATTN`, `FLASHINFER`).
216Otherwise, the prefill backend is selected automatically at runtime based on
217hardware and configuration.
218
219--8<-- "gen:table-mla-prefill"
220
221> **‡** Automatic selection tries FlashAttention first. On Blackwell
222> (SM100), the fallback order is TRT-LLM Ragged, FlashInfer, then
223> TokenSpeed MLA; for (qk_nope_head_dim=192, qk_rope_head_dim=64,
224> v_head_dim=256) TRT-LLM Ragged is tried before FlashAttention. On other
225> GPUs, only FlashAttention is considered.

234### DeepSeek V4 Decode Backends
235
236DeepSeek V4 sparse MLA uses its own decode backends, selected via
237`--attention-backend=<BACKEND>` (e.g., `FLASHMLA_SPARSE_DSV4`,
238`FLASHINFER_MLA_SPARSE_DSV4`). They share the V4 sparse-index
239pipeline (compressor + SWA + indexer, 256-token blocks, head 512);
240default on NVIDIA is `FLASHINFER_MLA_SPARSE_DSV4` on SM12x and
241`FLASHMLA_SPARSE_DSV4` on other supported CUDA architectures.
